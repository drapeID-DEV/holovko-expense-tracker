# Refactoring Report

## Lazy processing benchmark

Для проверки преимуществ ленивой обработки был создан файл `data/large.jsonl`
с 200 000 записей.

Сравнивались два подхода:

- чтение записей через генератор `read_rows_jsonl()`;
- загрузка всех записей в список через `list()`.

Результаты измерения:

| Подхід         | Записів |    Час | Peak memory |
| -------------- | ------: | -----: | ----------: |
| Lazy generator |  200000 | 1.31 s |     0.15 MB |
| List           |  200000 | 1.39 s |   108.28 MB |

Лениве читання використовує значно менше пам'яті, оскільки записи
обробляються по одній і не зберігаються всі одночасно в пам'яті.

При цьому час виконання в даному тесті відрізняється незначно.
